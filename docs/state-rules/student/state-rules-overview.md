# 学生向け状態ルール概要

## 目的

この文書は、学生向け画面における状態定義・表示差分・例外ケースを、実装前に整理するための最小設計メモである。

## 1. 共通状態定義

### 1-1. 学習状態の基本語彙

- 未提出
  - 学生が対象課題に対して提出していない状態。
  - 課題一覧では未着手として扱う。
  - エディターへの遷移は可能。ただし提出前の状態のため、保存済み状態と区別する。

- 提出済み
  - 課題の提出が完了している状態。
  - 提出後は再提出可否が画面ごとに制御される。
  - 評価結果画面へ遷移可能。

- 下書き
  - 課題の回答途中で、保存はしているが正式提出までは完了していない状態。
  - エディター内では保存済みと見なすが、提出状態には移行していない。

- 進行中
  - 学習や回答が継続中で、現在の作業状態が進行中であることを示す。
  - アンケートなどの回答画面で利用する。

- 完了
  - 必須入力や処理が完了している状態。
  - 画面上では完了済みと見なす。

- 未回答
  - アンケートや同意確認など、まだ入力が完了していない状態。

- 同意済み
  - 研究同意確認に同意した状態。

- 要更新
  - 教師側で課題や設定に更新が必要と判断された状態。
  - 学生画面では直接表示される場合と、教師画面でのみ表示される場合がある。

## 2. 画面別の状態と表示差分

### 2-1. ホーム画面

- 表示対象
  - 提出状況
  - 学習モード選択
  - 課題一覧

- 状態で変わる表示
  - 未提出: 課題一覧に通常表示
  - 提出済み: 完了済みの表示を追加
  - 下書き: 途中保存の状態を示す補足表示

- 操作可否
  - 学習モード選択は常時可能
  - 提出済み課題の再開可否は要判断

### 2-2. エディター画面

- 表示対象
  - 課題内容
  - ヒント
  - 保存状態
  - 実行状態

- 状態で変わる表示
  - 下書き: 保存済み表示、未提出のまま
  - 提出済み: 読み取り優先、編集可否を制限する

- 操作可否
  - 保存は常時可能
  - 提出済み後の編集は条件付きで制限する

### 2-3. 評価結果画面

- 表示対象
  - AI評価
  - 実行履歴
  - コードログ

- 状態で変わる表示
  - 提出済み: 評価結果を表示可能
  - 未提出: 画面に入れないか、未対応メッセージを表示

- 制約
  - 評価は学習の参考情報であり、成績評価とは分離する

### 2-4. アンケート画面

- 表示対象
  - 課題情報
  - フォーム項目
  - 進捗状態

- 状態で変わる表示
  - 未回答: 必須項目未完了表示
  - 進行中: 回答途中の表示
  - 完了: 送信済み表示

- 制約
  - 必須項目未入力時は送信不能

### 2-5. 同意確認画面

- 表示対象
  - 同意要求の説明
  - 同意 / 非同意選択

- 状態で変わる表示
  - 未回答: 選択待ち
  - 同意済み: 既回答表示

- 制約
  - 回答後は再表示されない想定

## 3. 例外ケース一覧

### 3-1. 課題が見つからない
- 画面遷移先で対象課題が存在しない場合、エラー表示またはホームへ戻す。
- ログやエラー文言は学生にとって理解しやすい文言にする。

### 3-2. 既に提出済みの課題を編集しようとした
- 既定では編集制限をかけるか、再提出フローを案内する。
- 画面上では「提出済みのため編集できません」のような案内を出す。

### 3-3. 保存せずに離脱した場合
- 画面遷移時に未保存の警告を出す。
- 画面上の保存状態表示と整合させる。

### 3-4. 同意未回答時のアンケートアクセス
- セッションまたは画面制御で、同意が未完了ならアクセス不可とする。

### 3-5. 必須項目が未入力
- 送信ボタンを無効化する、または該当項目をハイライトする。

## 4. 実装時の優先順

1. 状態名と意味を整理する
2. 画面ごとの表示差分を定義する
3. 例外ケースとメッセージを決める
4. ボタンの有効/無効を状態に紐付ける
5. 必要に応じて画面ごとのデータモデルを調整する

## 5. 実装に向けた注意点

- 状態と保存状態は区別する。
- 「提出済み」「下書き」「未提出」は学習状態であり、保存状態と混同しない。
- 学生画面の状態は、表示制御と操作制御の両方に影響する。
- 画面ごとの例外処理は、デザインではなく振る舞いとして明文化する。
