# 学生向け評価結果状態ルール

## 対象

- 評価結果画面
- AI評価の表示
- 実行履歴の確認
- 提出済み課題の再確認

## 1. 目的

この文書は、学生向け評価結果画面における状態定義、遷移条件、表示差分、例外処理を定義する。評価結果は学習のフィードバック情報として扱い、成績判定と混同しない。

## 2. 状態語彙

- 未提出
  - 評価対象の提出がない状態。
  - 評価結果画面へ遷移できないか、未対応メッセージを表示する。

- 評価待ち
  - 提出済みだが、評価処理が未完了の状態。
  - 一覧では「処理中」または「評価待ち」を表示する。

- 評価中
  - 実行または評価が進行中の状態。
  - 再アクセス時に再評価の再実行を禁止する場合がある。

- 評価完了
  - 結果が返却済みの状態。
  - フィードバック、点数、判定一覧を閲覧可能とする。

- 要修正
  - 結果上で再改善が必要と判断された状態。
  - 再提出または再挑戦の案内を表示する。

- 再提出対象
  - 再提出が許可される状態。
  - 提出画面へ遷移可能とする。

## 3. 状態遷移

| 現在状態 | 遷移先 | 条件 |
|---|---|---|
| 未提出 | 評価待ち | 提出を行ったとき |
| 評価待ち | 評価中 | 評価ジョブが開始したとき |
| 評価中 | 評価完了 | 評価処理が終了したとき |
| 評価完了 | 要修正 | 重大な改善が必要なとき |
| 要修正 | 再提出対象 | 再提出が可能なとき |
| 再提出対象 | 評価待ち | 再提出を実行したとき |

## 4. 表示差分

### 4-1. 一覧画面

- 未提出: 「未提出」を表示
- 評価待ち: 「評価待ち」または「処理中」を表示
- 評価中: 「評価中」を表示
- 評価完了: 「評価完了」または「結果あり」を表示
- 要修正: 「要修正」を表示
- 再提出対象: 「再提出可」を表示

### 4-2. 結果画面

- 評価完了: フィードバック本文、評価項目、履歴を表示
- 要修正: 改善ポイントと再挑戦導線を提示
- 再提出対象: 再提出ボタンや戻る導線を表示

## 5. 操作可否マトリクス

| 状態 | 閲覧 | 再評価 | 再提出 | 修正案の確認 | 戻る |
|---|---|---|---|---|---|
| 未提出 | 不可 | 不可 | 不可 | 不可 | 可 |
| 評価待ち | 可 | 不可 | 不可 | 不可 | 可 |
| 評価中 | 条件付き可 | 不可 | 不可 | 不可 | 可 |
| 評価完了 | 可 | 条件付き可 | 条件付き可 | 可 | 可 |
| 要修正 | 可 | 可 | 可 | 可 | 可 |
| 再提出対象 | 可 | 条件付き可 | 可 | 可 | 可 |

## 6. 例外処理

### 6-1. 評価結果がまだ返ってこない場合
- 「評価待ち」または「処理中」を表示し、再読込導線を案内する。
- 説明文は技術的な詳細ではなく、進捗を理解しやすい表現にする。
- 最新提出版を「評価中」として主表示し、直前の完了済み評価がある場合は提出版を明示して「前回の評価」として併記する。
- 前回の評価を最新提出版の評価結果として扱わない。

### 6-2. 提出データが存在しない場合
- 結果画面にアクセスさせず、課題一覧へ戻す。
- 画面表示はエラーではなく、指示文を優先する。

### 6-3. 再提出が許可されていない場合
- 画面上で再提出ボタンを無効化し、理由を表示する。

### 6-4. 評価開始後に再提出した場合
- 以前の提出版に対する評価処理を取り消さず、その提出版の評価履歴として保持する。
- 再提出は新しい提出版として保存し、その提出版に対する新しい評価処理を開始する。
- 再提出可否は評価状態ではなく、提出期限と教師の再提出設定で判定する。
- 既に評価完了済みでも学習の継続が可能な説明を行う。

### 6-5. 途中で評価が失敗した場合
- 「評価に失敗しました。評価を再試行できます」などのメッセージを表示する。
- 失敗理由の詳細は学生向けに簡潔にする。
- 提出をやり直さず、同じ提出版に対する評価処理だけを再試行する。
- 失敗した評価を上書きせず、再試行を新しい評価履歴として保存する。

## 7. 実装時の優先順

1. 評価状態の語彙を固定する
2. 未提出と評価完了を分けて管理する
3. 評価待ち・評価中の表示を設計する
4. 再提出可否条件を明文化する
5. エラー表示の文言を統一する

## 8. 実装に向けた注意点

- 評価結果は学習のフィードバック情報であり、成績判定とは分離する。
- 結果画面では「閲覧可能か」と「再提出可否」を分けて扱う。
- 適切な状態が画面ごとに異なるため、一覧と詳細画面の文言を統一する。

## 9. DB状態との同期（IC-004）

- 評価状態の正本は、提出版ごとの評価履歴が持つ評価状態（未評価 / 評価中 / 評価完了 / 失敗 / 要修正）とする。
- 一覧・進捗表示で参照する評価状態は、この正本を複製した表示専用の値とし、正本が更新されるタイミング（評価開始・完了・失敗・要修正判定）と同一の処理内で更新する。
- 本画面の語彙との対応：「評価待ち」＝未評価、「評価中」＝評価中、「評価完了」＝評価完了、「要修正」＝要修正、「再提出対象」＝要修正かつ再提出条件を満たす状態。
- 失敗後の再試行・要修正後の再評価は、既存の評価履歴を上書きせず新しい評価履歴として追加し、表示専用の値は対象提出版の最新評価履歴に合わせて更新する。
- 過去の提出版に対する評価履歴は、最新提出版の評価状態には影響させない。
