# プロンプト設計状態ルール

## 対象

- プロンプト設計機能
- プロンプト一覧の状態表示
- プロンプトの作成・編集・保存・適用

## 1. 目的

この文書は、教師向けプロンプト設計機能における状態定義、遷移条件、表示差分、例外処理を定義する。プロンプトは更新履歴を保持し、過去の状態を直接上書きしない設計とする。

## 2. 状態語彙

### 2-1. 基本状態

- 下書き
  - 新規作成中または編集中の状態。
  - 一覧では「下書き」と表示する。

- 設定済み
  - プロンプトが保存され、利用可能な状態。
  - 一覧では「設定済み」と表示する。

- 再評価対象
  - 既存のプロンプトに対して、評価基準や文言の見直しが必要な状態。
  - 一覧では「要確認」または「再評価対象」と表示する。

- 版管理済み
  - 変更履歴が記録され、特定バージョンとして固定された状態。
  - 直接上書きではなく、新しい版を作成して管理する。

## 3. バージョン管理ルール

- バージョンは `v1`, `v2`, `v2.1` のように、階層と更新単位を明示する。
- 既存のバージョンを直接上書きしない。
- 変更時は新しい下書きを作成し、承認後に適用または新版として保存する。
- 履歴画面では、過去バージョンを選択して閲覧・比較できる。

## 4. 状態遷移

| 現在状態 | 遷移先 | 条件 |
|---|---|---|
| 下書き | 設定済み | 保存・適用を行ったとき |
| 下書き | 再評価対象 | 既存設定との矛盾や改善要求が発生したとき |
| 設定済み | 再評価対象 | 評価観点や設計要件に変更があったとき |
| 再評価対象 | 下書き | 修正を開始したとき |
| 設定済み | 版管理済み | 新規版として確定したとき |
| 版管理済み | 下書き | 新しい改善案を作成したとき |

## 5. 表示差分

### 5-1. 一覧画面

- 下書き: 「下書き」バッジ表示
- 設定済み: 「設定済み」バッジ表示
- 再評価対象: 「再評価対象」または「要確認」表示
- 版管理済み: バージョン番号を併記して表示

### 5-2. 編集画面

- 下書き: 保存・プレビュー・適用の導線を表示
- 設定済み: 再編集・比較・履歴閲覧の導線を表示
- 再評価対象: 差分説明と修正案入力欄を表示

## 6. 操作可否マトリクス

| 状態 | 編集 | 保存 | 適用 | 履歴閲覧 | 削除 |
|---|---|---|---|---|---|
| 下書き | 可 | 可 | 条件付き可 | 可 | 可 |
| 設定済み | 可 | 可 | 可 | 可 | 条件付き可 |
| 再評価対象 | 可 | 可 | 条件付き可 | 可 | 条件付き可 |
| 版管理済み | 条件付き可 | 可 | 不可 | 可 | 不可 |

### 補足

- 版管理済みは新規版を作らない限り直接更新しない。
- 適用は、設計の整合性が確認できてから実施する。

## 7. 例外処理

### 7-1. 設定済みプロンプトを編集した場合
- 直接上書きではなく、新しい下書きを生成する。
- 既存版は履歴として保持する。

### 7-2. 適用前のプロンプトが不整合の場合
- 保存は可能でも適用は不可とし、差分と注意書きを表示する。

### 7-3. 過去バージョンを表示しようとした場合
- 読み取り専用として表示し、編集は不可とする。

### 7-4. 必須項目が未入力の場合
- 保存可能な場合と適用不可な場合を分ける。
- 必須項目の欠落時はフォーム上でハイライトする。

### 7-5. 一部プロンプトが課題に紐づいている場合
- 対象課題との差分が大きい場合は、再評価対象へ切り替える。
- 適用前に影響範囲の確認を行う。

## 8. 課題状態との関連ルール

- 未適用の下書きプロンプトの編集は課題状態と別管理とする。
- 公開中課題で使用するプロンプト版の切替は評価条件の変更として扱う。
- 対象クラスの全生徒が未着手の場合は課題を `要更新` とし、再公開時に新しいプロンプト版を適用する。再公開までは直前の適用版を維持する。
- 一人でも学習開始済みの場合でも、教師が「設定して再評価する」を明示確認し、対象生徒・評価差分プレビューを確認した全体再評価に限って、同じ課題の現在適用版を新しいプロンプト版へ切り替えられる。プロンプト以外の学習条件を変更する場合は新しい課題として複製する。
- 全体再評価は対象となる各生徒の最新提出を再評価し、新しい評価履歴として保存する。旧評価行・提出・当時使用したプロンプト版は変更・削除しない。処理中の通常評価は開始時に固定した版を使い続ける。
- 評価済み・評価中の提出では、各評価行が実際に使用したプロンプト版への参照を保持し、後から上書きしない。
- 社会的影響が大きい設定変更は `再評価対象` として扱う。
- 課題公開時にプロンプトが未設定の場合、公開可否は `要更新` または `下書き` とする。

## 8-2. 現在適用版の保持と固定タイミング（IC-007）

- 各課題は常に1つの「現在適用版」プロンプトを保持する。現在適用版は課題に対して1件のみ存在し、一覧・編集画面・評価処理のいずれも、課題から現在適用版を一意に参照できるようにする。
- 現在適用版の切替は、教師が対象生徒と評価差分のプレビューを確認した後、「設定して再評価する」を確定した時点で行う。確定前（評価例確認まで）は、新しく作成した版は「下書き」または「設定済み」のままとし、現在適用版は従来の版を維持する。切替と再評価ジョブの作成は一貫して扱い、確定に失敗した場合は従来版を維持する。
- 評価処理（提出に対する評価の開始）が始まる時点で、対象課題の現在適用版を評価履歴へ固定して記録する。固定後は、教師が別のプロンプト版へ切り替えても、既に開始済みの評価処理の結果には影響させない。
- 新しい版を作成する条件は、既存の設定済み・版管理済みプロンプトを直接編集しようとした場合とする。この場合は内容を上書きせず、新しい版番号（例：`v2`、`v2.1`）の下書きとして保存し、現在適用版はそのまま維持する。
- 未適用（下書き）段階のプロンプトは、同一版のまま上書き保存できる。
- 全体再評価の各結果は元評価を上書きしない。各新規評価行に新プロンプト版を固定し、進捗・部分失敗・再試行を再評価ジョブ単位で追跡する。

## 9. 責務分担

### 9-1. Servlet

- 保存・適用・履歴表示のリクエストを受ける。
- 入力値の妥当性と状態遷移の正当性を検証する。

### 9-2. Control

- プロンプトの状態遷移と版管理を担当する。
- 変更履歴と再評価対象の判定ロジックを実装する。

### 9-3. Repository

- プロンプト本体とバージョン履歴を保存する。
- 版管理済みプロンプトと編集中下書きを分離して保持する。

## 10. 実装時の優先順

1. 状態語彙を固定する
2. バージョン管理ルールを決める
3. 保存・適用・履歴閲覧の可否を定義する
4. 再評価対象への切り替え条件を整理する
5. 例外メッセージを統一する

## 11. 実装に向けた注意点

- 直接上書きは避け、新しい版または新しい下書きを作る。
- 履歴は表示用として保持し、編集前提で使わない。
- 画面上のバッジ表示とデータ状態を一致させる。
- 課題の公開状態とプロンプト状態は別物として管理する。
