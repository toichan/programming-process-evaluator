# 教師向け進捗状態ルール

## 対象

- 教師の進捗ダッシュボード
- 学生ごとの学習進行状況
- 提出状況の集計
- 進行中/完了/要対応の判定

## 1. 目的

この文書は、教師向け進捗画面における状態定義、遷移条件、表示差分、例外処理を定義する。進捗情報は課題状態ではなく、学習の継続状態として管理する。

## 2. 状態語彙

- 未着手
  - 学生が対象学習や課題を開始していない状態。

- 進行中
  - 学習または提出が継続している状態。

- 提出済み
  - 課題または回答が提出されている状態。

- 評価待ち
  - 提出済みだが、教師の評価が未完了の状態。

- 完了
  - 学習または評価が完了した状態。

- 要対応
  - 期日超過や修正依頼など、教師の対応が必要な状態。

## 3. 状態遷移

| 現在状態 | 遷移先 | 条件 |
|---|---|---|
| 未着手 | 進行中 | 学生が課題または学習を開始したとき |
| 進行中 | 提出済み | 提出または完了を行ったとき |
| 提出済み | 評価待ち | 教師評価を待っているとき |
| 評価待ち | 完了 | 評価が確定したとき |
| 完了 | 要対応 | 修正や再提出が必要になったとき |
| 要対応 | 進行中 | 再作業が開始されたとき |

## 4. 表示差分

### 4-1. ダッシュボード

- 未着手: 「未着手」表示
- 進行中: 「進行中」表示
- 提出済み: 「提出済み」表示
- 評価待ち: 「評価待ち」表示
- 完了: 「完了」表示
- 要対応: 「要対応」表示

### 4-2. 学生別一覧

- 各学生に対して、状態バッジと最終更新時刻を表示する。
- 要対応が多い学生は優先度の高い表示を行う。

## 5. 操作可否マトリクス

| 状態 | 確認 | 連絡 | 評価 | 再対応 | 表示の更新 |
|---|---|---|---|---|---|
| 未着手 | 可 | 可 | 不可 | 不可 | 可 |
| 進行中 | 可 | 条件付き可 | 条件付き可 | 不可 | 可 |
| 提出済み | 可 | 可 | 可 | 不可 | 可 |
| 評価待ち | 可 | 可 | 可 | 不可 | 可 |
| 完了 | 可 | 可 | 不可 | 条件付き可 | 可 |
| 要対応 | 可 | 可 | 可 | 可 | 可 |

## 6. 例外処理

### 6-1. 期限切れが発生した場合
- 状態を「要対応」または「期限超過」に切り替える。
- 一覧表示に注意ラベルを付す。

### 6-2. 提出物が途中保存のみの場合
- 完了状態にせず、進行中または一時保存として扱う。
- 提出済みとの混同を避ける。

### 6-3. 学生が再提出した場合
- 既存の評価済みあとに再評価対象として扱い、履歴を残す。

## 7. 実装時の優先順

1. 進行中と完了を明確に区別する
2. 提出済みと評価待ちを分ける
3. 要対応の判定条件を定義する
4. 学生別一覧の表示優先度を定める
5. 期限切れ時の表示を統一する

## 8. 実装に向けた注意点

- 進捗状態は学習の継続状況であり、評価結果と混同しない。
- 提出済みと評価済みは別状態として扱う。
- 一覧画面では状態の見え方を簡潔にし、詳細画面で説明を補う。
