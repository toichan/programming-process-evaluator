# 画面遷移図（Screen Flow Diagram）

## 目的
本ドキュメントは、プログラミング・プロセス・エバリュエーターの**画面遷移図**です。  
`screen-flow-diagram/webapp/` 以下で実装されるプロトタイプの画面構成と遷移フローを定義します。

**注記**：  
- 本ドキュメントは画面遷移・UI構成の確認を目的としており、実装の詳細設計ではありません  
- 実装時の詳細設計（エラーハンドリング、API仕様など）は別途ドキュメント化します  
- ここで定義した画面遷移は、実装中に変更される可能性があります

## 実装形式

- **HTML**：`screen-flow-diagram/webapp/WEB-INF/` 以下に配置
- **共通スタイル**：`screen-flow-diagram/webapp/css/template/template.css`
- **ページごとのスタイル**：各フォルダ配下の CSS ファイル
- **スクリプト**：JavaScript（ナビゲーション、モーダル操作など）

## 実装方針

1. 生徒向け画面（実装済み）との共通ヘッダー・ナビゲーション構造を活用
2. 教師向け画面は、サイドメニューナビゲーション + メイン領域の構成を統一
3. 各画面は独立したHTMLファイルとして実装
4. ポップアップ・モーダル表示は JavaScript で実装
5. Bootstrap をベースに、共通CSS で統一デザインを実現

## 共通表示要件

- パソコン・タブレット・スマートフォンで利用できるレスポンシブデザインとし、320 CSS px以上で通常の各画面を表示する。
- 画面幅に応じてナビゲーション、カラム、カード、フォーム、操作ボタンを再配置し、画面幅1024 CSS px未満を理由とする利用案内への置き換えは行わない。
- ページ全体の横方向へのはみ出しを防ぐ。コード編集欄など横幅が必要な領域では、その領域内に限り横スクロールを許容する。
- 画面幅が変わっても、URL・ログイン状態・画面内状態を維持する。

## 画面構成と遷移
本プロトタイプでは、以下の画面構成と遷移を定義します。

### 生徒向け画面構成
- **学生ログイン**
  - 画面項目：ID、パスワード、ログインボタン、説明文
  - ヘルプボタンからモーダルを開き、ログインIDを忘れた場合またはパスワード再設定が必要な場合は担当者へ問い合わせるよう案内する。外部フォームへの遷移は行わない
  - 遷移：ログイン成功 → 研究協力同意確認（初回） / 課題選択（2回目以降）
- **生徒ヘルプ**
  - 共通ヘッダーのヘルプボタンから、提出課題（選択→作成/保存→提出→評価/ログ→対象の場合のアンケート）と授業演習（作成→保存→実行、提出課題とは別）の図解付きモーダルを表示する
  - 操作に困った場合は担当者へ問い合わせるよう案内する。画面遷移・外部フォーム起動は行わない
- **共通ヘッダーの通知**
  - 通知一覧は設けず、通知アイコンは「準備中」の非操作表示とする。固定件数・サンプル通知・遷移リンクを表示しない
- **アカウント情報**
  - 生徒ID（student_id）はログインIDと同一とし、画面右上・メニュー・登録情報・本人のパスワード操作履歴で統一する。右上のユーザーメニューには生徒ID・所属クラス・学校を表示し、所属情報はDBから取得する。生徒の別表示名は表示しない。教師ID（teacher_id）もログインIDと同一とする
  - パスワード変更画面は[機能仕様書のパスワード変更画面](function-specification.md)に従い、入力中の要件チェック・不足理由・更新ボタンの有効制御を表示する。初回／リセット後の強制変更中は戻るボタンを無効にする
  - パスワード更新成功後は、強制変更ならホーム、通常の任意変更ならアカウント情報へ戻る。遷移先で共通feedbackの完了通知を1回表示する
  - 画面項目：DBから取得した生徒ID、学校情報、クラス情報、初回パスワード変更の要否、パスワード変更可否と導線。レベル名・番号は非表示。変更不可の場合は灰色の無効ボタンと「あなたのアカウントでは、パスワード変更が許可されていません。必要な場合は担当者へご相談ください。」を表示する
  - 遷移：ホームまたは共通ヘッダーのユーザーメニューから遷移し、パスワード変更画面またはホームへ戻る
- **パスワード変更**
  - 画面項目：現在のパスワード、新しいパスワード、新しいパスワード（確認用）、パスワード要件、更新ボタン
  - 遷移：初回ログイン時またはアカウント情報画面から遷移し、更新完了後はアカウント情報画面へ戻る
- **研究協力同意確認**
  - 画面項目：研究協力説明文、同意する・同意しないボタン
  - 遷移：同意完了 → 課題選択、同意しない場合も課題選択へ遷移可能
  - 回答後も共通ヘッダーの「研究同意」から再訪し、回答を変更できる。変更前は確認ダイアログで変更前後の内容と影響を確認し、確定後にホームへ戻る
- **課題選択**
  - 画面項目：初級・中級・上級の課題カード、課題説明、想定入出力例、授業演習導線
  - 遷移：課題選択 → エディター画面 / 授業演習画面

  - エディター設定ダイアログでは課題エディターと同じアカウント別設定（文字サイズ10〜24px、コードの折り返し、インデント幅2/4スペース、配色）を使用し、変更は即時反映して両エディターで共有する。初期値は16px、折り返しなし、4スペース、暗色テーマ。コード行数に応じてエディターの縦幅を内容に合わせて広げる。
  - 実行結果はコード編集カードの外に独立カードとしてコード欄の下へ常時表示し、折りたたまない。コード欄の編集幅を保ち、結果は次の実行まで保持する。カード内の「入出力」「エラー」ボタンで表示を切り替え、エラーがある場合は「エラー」ボタンに警告を表示する。「結果は次の実行まで表示されます。」「コードを見ながら確認できます。」の説明文、および「標準出力」「標準エラー」の見出しは表示しない。
  - 遷移：ホームから遷移し、共通ヘッダーまたはホームへ戻る
- **エディター**
  - ツールバーは課題名と右寄せの操作を同じ段に配置し、長い課題名は残り幅で折り返す。ダウンロードだけ説明・読み上げ名付きの小型アイコンボタンにし、保存・実行・提出は文字を残す。想定入出力欄は余白を抑え、内容に応じた高さにする。詳細は[機能仕様書](./function-specification.md)を参照する。
  - 画面項目：Pythonコードエディター、ダウンロードボタン、保存ボタン、実行ボタン、提出ボタン、エディター設定ダイアログ（小さな歯車アイコンの設定ボタンをファイル名タブ行の右端に配置）、課題情報カード（課題・ヒント）、コード欄下の実行結果カード（対話型ターミナル）、コードログ
  - ダウンロードボタンは編集中のコード（未保存分を含む）を課題名`.py`として取得する。サーバー上の下書き・保存状態・コードログは変更しない。外部での編集内容はログへ記録されない。
  - 設定ダイアログでは文字サイズ（10〜24px）、コードの折り返し、インデント幅（2/4スペース）、配色（暗色/明色/高コントラスト）を変更する。変更は即時反映し、ユーザーアカウントへ保存して別端末にも引き継ぐ。設定を初期値に戻せる。初期値は16px、折り返しなし、4スペース、暗色テーマとする。折り返しが無効の場合は、ページ幅を拡大せずエディター内で横スクロールして長い行を確認できる。コード行数に応じてエディターの縦幅を内容に合わせて広げる。
  - 課題情報と実行結果は別々のカードに表示する。課題情報カードは常時表示し、折りたたまない。コード欄と課題情報カードの幅は固定し、幅調整機能を設けない。実行結果カードはコード編集カードの下に常時表示し、折りたたまない。実行結果カードにはターミナル領域を一つだけ配置し、実行中に入力を送信できる入力欄と、入力・標準出力・標準エラーを発生順に表示する履歴を同じ領域に表示する。標準出力と標準エラーのタブ切替や別の標準入力欄は設けず、結果は次の実行まで保持する。「結果は次の実行まで表示されます。」「コードを見ながら確認できます。」の説明文、および「標準出力」「標準エラー」の見出しは表示しない。
  - 実行状態と最終実行時刻はターミナルカード内に表示する。狭い画面でも入力欄をターミナル内に保ち、履歴だけをスクロールできるようにする。
  - 操作：実行ボタンを押したら確認ダイアログを挟まずコードを実行し、ターミナルまで自動スクロールする。プログラムが入力待ちになったらターミナル内で一行ずつ入力して送信し、標準出力と標準エラーを発生順に同じ履歴へ追記する。端末入力・標準出力・標準エラーのいずれも30秒間発生しない場合に実行を終了し、実行全体は最大60秒、CPU使用時間は最大4秒とする。提出ボタンでは「課題を提出しますか？」の事前確認を重ねず、入出力チェック結果のモーダルで内容を確認する。フッターの「提出する」ボタンの直上に「期限内の再提出は可能です」と添えて表示し、最終ボタンの操作で確定する。提出期限内の再提出は対象クラスの設定にかかわらず許可し、教師向けのクラス別再提出設定は設けない。期限後の再提出は許可しない。
  - 遷移：コード実行後はコード欄下のターミナルまでスクロールして、実行状況と対話履歴を表示する。保存時は画面内フィードバックを表示する。提出確定後は評価表示へ

### 画面間遷移のイメージ
**生徒側**：
1. ログイン後、初回かどうかで「同意確認」または「課題選択」へ進む
2. 共通ヘッダーのユーザーメニューから、必要に応じてアカウント情報画面を確認する
3. セキュリティレベル2の生徒は、必要に応じてパスワード変更画面からパスワードを更新する

5. 課題演習ではエディターに進み、コード実行・保存を行う
6. エディターでの成果は評価画面に反映され、必要に応じてアンケートへ遷移する

**教師側**：
1. ログイン → アカウント管理画面（初期表示）
2. サイドメニューから目的の機能を選択
3. 各機能内で「一覧 → 詳細」のフローを繰り返す
4. 必要に応じてCSVエクスポート、再評価実行などの操作を実行
5. （未実装）adminログイン時は教師アカウント管理へ遷移

画面遷移図実装時に従う基本方針：

### ナビゲーション構造
- **共通ヘッダー**：ロゴ、教師情報、本人の「アカウント」リンク、ログアウトボタンを配置（生徒向けに準じる）。本人画面では生徒アカウント管理のサイドメニューを選択状態にしない
- **サイドメニュー**：アカウント情報管理を入口として、以下機能を選択可能
  - 課題進捗確認
  - 授業演習コード確認
  - コード配信
  - 提出課題確認
  - 評価確認
  - アンケート結果確認
  - 課題編集
  - プロンプト設計
- **パンくずナビゲーション**：詳細画面で現在位置を明示

### 共通要素
- **リスト画面**：テーブル形式で表示、ソート・フィルタ機能搭載
- **詳細画面**：行クリックで遷移、タブ分けで複数情報を管理
- **エクスポート機能**：CSVダウンロード（UTF-8 BOM付き）
- **確認ダイアログ**：削除・再評価などの重要操作前に表示
- **エラー通知**：トースト表示またはモーダル確認
- **日時表示**：`YYYY-MM-DD HH:MM:SS` で統一

### 画面遷移の基本フロー
1. ログイン → アカウント管理（初期画面）
2. サイドメニューで機能選択 → 一覧画面
3. 一覧から行選択 → 詳細画面
4. 詳細から操作（エクスポート、再評価など）→ 確認ダイアログ → 実行

## 次フェーズ

本ドキュメントで画面遷移を確定した後、以下の流れで実装を進めます：

1. **Servlet と Control の実装**：Servlet がログイン・各機能の HTTP 入口を担当し、Control がアプリケーション処理を担当
2. **JSPビューの実装**：共通テンプレート化し、各画面を段階実装
3. **JavaScriptの実装**：フィルタ、ソート、AJAX自動更新
4. **スタイル調整**：Bootstrap + 独自CSS で統一UI実現
