# アンケート実装の確認事項

アンケート回答実装に関する確認事項と、ユーザー合意済みの決定を記録する。追加の仕様判断が必要になった場合は、選択肢と影響を記録してから確認する。

関連資料: [生徒の評価・コードログ・アンケート実装計画](./student-evaluation-survey.md)、[機能仕様書](../../function-specification.md)、[実装契約](../implementation-contract.md)、[DBテーブル定義](../../database-design/table-definitions.md)

## Q1. 回答行の所有者と研究用識別子

- 決定済み（2026-10-03）: アンケート研究データでは `users.user_id` を研究用識別子としてそのまま使用し、別IDへの置換は行わない。氏名・出席番号・ログインIDは研究データに含めない。
- 取扱上の注意: `user_id` は氏名等を含まない内部キーだが、アプリ内ではアカウント表を介してログインID等と対応づけ可能である。このため研究データは完全匿名ではなく仮名化されたデータとして扱い、対応関係を参照できる権限を制限する。
- スコープ: この決定はアンケート回答およびその研究用データに適用する。Geminiへの送信IDは既存のAI連携仕様に従い、別途変更しない。

## Q2. アンケートの対象単位と評価との関連

- 決定済み（2026-10-04ユーザー指示）: 本システムのアンケートは課題別に限定し、その課題の完了済みシステム評価を提示する。全体アンケートは本システム内では実装せず、保留・後続実装の対象から除外する。仕様は[機能仕様書第105版](../../function-specification.md)を参照。
- 実装条件: 学生ホームから対象課題のsurveyへ遷移し、サーバー側で本人の同意・課題対象性・当該課題に紐づく完了済みevaluationを検証する。

## Q3. 回答途中の保存と開始タイミング

- 決定済み（2026-10-03）: 画面を開いただけ、または入力欄へ記入しただけではDBの回答状態を変更しない。最初の明示的な「下書き保存」を受理した時点で回答を開始・保存し、以後は保存済みの内容から再開できる。
- 実装条件: GETで書き込みを行わない。保存前に離脱した未保存入力は再開対象外とし、画面上で保存済み状態と区別する。

## Q4. 設問変更と既存回答の版固定

- 決定済み（2026-10-03）: 同じ生徒・課題アンケート・評価IDの提出済み回答は再回答させず、読み取り専用で表示する。回答中なら保存済み下書きを再開する。評価IDが異なる場合は新しい回答を作成し、以前の回答も履歴から参照できるようにする。
- 設問変更: 既存の回答解釈を変えないよう、回答開始後の設問・選択肢は変更しない。内容変更が必要な場合は新しい `survey_id` で作成し、旧surveyと回答履歴を保持する。専用の版番号カラムは今回追加しない。
- DB上の一意性: `(student_user_id, survey_id, evaluation_id)` を一意とし、二重送信でも同じ対象の回答履歴を重複作成しない。工程8の課題別surveyでは `evaluation_id` 必須。

## 実装環境で確認した前提

- 2026-10-03時点のローカルDBに有効な課題別surveyおよびsurvey回答は存在しない。架空の回答や研究データを作成せず、画面・保存機能はDB上で教師等が設定したactive survey/question/optionを読み込む実装とする。
