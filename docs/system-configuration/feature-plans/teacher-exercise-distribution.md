# 授業演習コード配信 実装計画

## 目的と範囲

- 教師が作成したフォルダ/ファイル構成と初期コードを、担当クラスの生徒へ配信する。
- 下書き保存、単一校内の複数クラス指定、クラス別即時/予約配信、予約日時変更、停止/再開、再配信、履歴表示を実装する。
- 再配信は必ず新しいフォルダへ追加する。生徒の既存コードを上書き・削除しない。
- 対象外: 課題公開/課題配信、提出確認、教師の授業演習コード閲覧機能。
- 画面プロトタイプは参照専用とし、プロトタイプ自体は変更しない。本実装の画面再現が明示依頼された場合は、承認済み機能仕様と実際のDB/API契約に沿って既存UIを再現する。

## 前提・決定事項

- ユーザー承認済み: 同一テンプレートを同じクラスへ再配信しても既存データを上書きしない。`（再配信）`、`（再配信2）`の順でルートフォルダを分ける。
- 再配信は新しい`distributions`/`distribution_targets`を作成し、過去の配信記録を変更しない。各実行はテンプレート名・ルート名・項目をスナップショットし、後のテンプレート編集から独立させる。
- 既存の教師権限コード`code-distribution`を使用する。教師機能権限に加え、担当学校/クラスの両方をサーバー側で検証する。
- 配信時点の有効なクラス在籍者を対象とする。停止は未配信/予約中の対象に適用し、既に反映された生徒データは撤回しない。
- 同一配信の再試行は`(distribution_target_id, student_user_id)`で冪等にする。
- `overwrite_policy`は既存DB互換のため保持するが、有効値を`append`に限定する。
- ルート名/ファイルは配信演習領域として保存し、生徒側の授業演習統合機能と`source_exercise_id`による追跡を維持する。
- この着手時点で確認が必要な仕様未決事項はない。予約日時は既存の`DATETIME`とローカル入力規約に従う。
- 1回の配信は1校のみを対象とし、その学校の担当クラスは複数選択できる。複数校にまたがる配信対象はサーバー側でも拒否する。

| 操作 | ロール・所有範囲 | DBへの変更 | 成功・失敗時の表示 |

| 一覧/履歴 | 有効教師、`code-distribution` | 担当学校のデータのみ取得 | テンプレート・配信・クラス別状態と履歴を表示 |
