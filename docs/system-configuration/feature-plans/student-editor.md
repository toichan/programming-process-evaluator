# 生徒エディター実装計画

## 目的と範囲

- 利用者に提供する動作: 生徒が割り当てられた公開課題を読み、Pythonコードを編集・保存・実行し、入出力を確認して提出できる。
- 今回実装する範囲: 本人の課題割当確認、サーバー側下書きの復元と楽観ロック、手動保存・30秒スナップショット、コードログ、隔離Docker実行、課題テストケース確認、提出・再提出状態遷移。
- 今回対象外: 教師向け課題作成・公開、評価結果画面、外部ファイルの読み込み、授業演習エディター。課題エディターから編集中コードを書き出す操作は提供するが、書き出しはサーバー保存・コードログへ影響しない。

|---|---|---|---|---|---|---|

| 保存 / 定期記録 | 課題参加者本人 | コード、期待する下書き更新日時、イベント種別、CSRFトークン | 本人の参加行と最新更新日時 | 参加下書き、学習・進捗・保存状態、追記型コードログ | 初回保存で学習中、以後は保存済み | 保存成功後のみ成功表示。更新競合は409で最新内容の再読込を促す |

| 対話型コード実行 | 課題参加者本人 | コード、実行中の一行入力、CSRFトークン | 本人の参加行と実行セッション | 実行結果とコードログ | 課題状態は変更しない | 入力・標準出力・標準エラーを同じ履歴に逐次表示。端末無通信30秒、全体60秒、CPU4秒で終了 |
| 再提出編集開始 | 提出期限内の生徒本人 | 課題割当ID、CSRFトークン | 最新提出、期限 | 最新提出をコピーした下書き、参加状態、編集ログ | 学習中へ戻す | 元提出は不変。期限外など条件を満たさない場合は理由を表示 |
| 提出確認・確定 | 提出条件を満たす生徒本人 | 下書き版、確認ID、冪等キー、CSRFトークン | 最新下書き、期限・初回期限後提出方針、テストケース、確認実行結果 | 新しい提出版、実行・テスト結果、コードログ、参加状態 | 受理済み・評価待ち | 入出力チェック結果を確認後に確定。不一致は表示するが拒否しない。条件違反・競合・重複は履歴を増やさず説明する |

## 検証計画

- ビルド / テスト: `docker compose exec -T app gradle test build --warning-mode all`
- 正常系: 対象課題表示、下書き復元、手動保存、30秒記録、実行、テストケース確認、提出・再提出。
- 状態遷移・操作可否: 未提出、保存済み、提出済み、再提出可能、期限超過、再提出編集状態。
- 権限境界・直接URL: 別生徒、非所属クラス、未公開・終了割当からのアクセス拒否、CSRFなしPOST拒否。
